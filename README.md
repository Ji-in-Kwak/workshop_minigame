# LOOP · 우리 팀의 연결

약 17명이 휴대폰으로 참여하는 개인전 슬리더링크 워크샵입니다. Next.js App Router와 TypeScript를 사용하며 Vercel 배포를 지원합니다.

## 로컬 실행

Node.js 22 이상을 사용하세요.

```sh
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 열고 **진행자 모드 → 방 만들기**를 선택합니다. DB 설정이 없으면 개발 환경에서만 `.local-data/`에 방 데이터를 보관합니다. 서버 재시작 후에도 같은 브라우저의 쿠키와 데이터 파일이 남아 있으면 복구됩니다. 로컬 파일 모드는 단일 Node 프로세스의 리허설용입니다.

같은 Wi-Fi의 휴대폰에서 테스트하려면 PC의 LAN IP로 접속하세요(예: `http://192.168.0.10:3000`). 진행자도 해당 주소로 방을 열어야 QR에 휴대폰에서 접근 가능한 주소가 들어갑니다. 로컬 HTTP에서 클립보드 기능이 제한되면 QR이나 방 코드를 사용하세요.

## Supabase와 Vercel 배포

1. Supabase 프로젝트를 생성합니다. SQL Editor에서 `supabase/migrations/202611250001_workshop.sql`을 실행합니다.
2. Supabase **Connect → Transaction pooler**의 연결 문자열을 복사합니다. 데이터베이스 비밀번호의 특수문자는 URL 인코딩합니다.
3. Vercel에서 이 저장소를 가져오고 Framework를 **Next.js**로 선택합니다. 빌드 명령은 `npm run build`입니다.
4. Vercel 환경변수에 `DATABASE_URL`을 설정합니다. 이 값은 서버 전용이며 `NEXT_PUBLIC_` 접두사를 붙이지 마세요.
5. 필요하면 `NEXT_PUBLIC_APP_URL`에 참가자가 접속할 HTTPS 주소를 설정합니다(끝의 슬래시 제외). 비워 두면 현재 브라우저 주소를 사용합니다. 커스텀 도메인 변경 후에는 이 값도 갱신해야 합니다.
6. 배포합니다. Supabase는 서버에서 TLS로 연결하며, transaction pooler 호환을 위해 prepared statement를 비활성화합니다.
7. 배포된 주소에서 새 방을 만들고 두 기기로 시작·제출·마감·결과 공개를 리허설하세요. 참가자가 Vercel 계정 없이 URL에 접근할 수 있도록 배포 보호 설정을 확인하세요.

`.env.example`에 환경변수 예시가 있습니다. 로컬에서 DB를 사용하려면 `.env.local`에 설정하세요. Vercel에서는 파일 저장을 허용하지 않으며 DB 미설정 시 방 생성과 입장 API가 503을 반환합니다. 프로덕션 빌드를 로컬 파일 모드로 리허설할 때에만 `ALLOW_LOCAL_STORE=true`를 설정할 수 있습니다. 이 설정도 Vercel에서는 무시됩니다.

## 현장 진행

1. 진행자 기기에서 방을 만들고 해당 탭을 유지합니다. 관리 권한은 7일 유효한 HttpOnly 쿠키로 저장됩니다. 진행자 브라우저의 쿠키를 지우면 관리 권한이 사라집니다.
2. **공용 화면 열기**로 프로젝터용 화면을 엽니다. 별도 PC에서는 **다른 기기용 화면 링크 복사**를 사용합니다. 이 링크에는 조회 전용 접속 토큰이 포함되므로 참가 링크와 구분하세요. 접속 후 토큰은 URL에서 제거됩니다.
3. 참가자들은 QR 또는 방 코드와 닉네임으로 입장합니다. 중복 닉네임은 사용할 수 없습니다. 기본 목표는 17명이며 최대 30명까지 허용합니다.
4. 기본 구성은 5×5 연습 3분 → 5×5 본게임 5분 → 6×6 본게임 8분입니다. 시작 전에 문제와 시간을 조정할 수 있습니다.
5. 각 라운드는 진행자가 시작합니다. 오답은 오류 표시와 함께 재도전을 허용하고, 정답은 최초 제출 시각으로 확정합니다. 자동 마감 이후에는 서버에서도 제출을 거절합니다.
6. **제출 마감 → 결과 공개 → 다음 라운드 준비** 순서로 조작합니다. 마지막에는 **워크샵 마무리하기**를 누릅니다.

순위는 본게임 정답 수 우선, 동률이면 정답 문제 풀이시간 합계(밀리초 단위) 우선이며 완전히 같으면 공동 순위입니다. 화면 시간은 초 단위로 올림해 표시하므로 표시상 같은 시간이어도 순위가 다를 수 있습니다. 연습은 순위에 포함하지 않습니다. 진행 중 입장한 참가자는 다음 라운드부터 참여합니다. 연결이 끊겨도 서버의 제한시간은 계속 흐릅니다. 중도 일시정지와 다른 기기로의 참가 기록 이전은 지원하지 않습니다.

## 구성과 API

- `/`: 방 입장, 방 생성, 게임 규칙
- `/practice`: 시간 제한 없는 혼자 연습(DB 없이 사용 가능)
- `/room/[code]`: 참가자 화면
- `/host/[code]`: 진행자 화면
- `/display/[code]`: 조회 전용 공용 화면
- `POST /api/rooms`: 방 생성 및 진행자·공용 화면 쿠키 발급
- `GET /api/rooms/[code]?mode=player|host|display`: 권한별 상태 조회
- `POST /api/rooms/[code]`: `join`, `display-access`, `configure`, `start`, `submit`, `close`, `reveal`, `next`, `finish`
- `GET /api/practice`: 정답을 제외한 연습 문제

참가자 입장은 `{type:"join", nickname}`이며 참가자 토큰은 HttpOnly 쿠키에 저장합니다. 설정은 `{type:"configure", puzzleId, durationSeconds}`, 제출은 `{type:"submit", roundIndex, lines, requestId}`입니다. `roundIndex`는 0부터 시작하고 `requestId`에는 UUID를 사용합니다. 동일한 참가자의 동일 제출 식별자 재전송은 기존 결과를 반환합니다.

선 번호는 가로 선을 위에서 아래로, 각 행에서 왼쪽부터 먼저 부여하고 이후 세로 선을 위에서 아래로 각 행의 왼쪽부터 부여합니다. `src/lib/slitherlink.ts`의 `topology()`가 공통 정의입니다. 금지 표시는 채점 API에 전송하지 않습니다.

상태는 2초 간격으로 조회합니다. 정답 데이터는 서버 전용 카탈로그에 있고, 참가자에게는 시작 전에 문제 숫자를 보내지 않습니다. 게임 중 타인의 풀이·완료 시각·순위를 공개하지 않습니다. 방의 참가자·라운드·제출은 하나의 JSONB 집계로 저장하며 PostgreSQL 행 잠금 트랜잭션으로 여러 Vercel 인스턴스의 동시 변경을 직렬화합니다. 브라우저의 Supabase 직접 접근은 허용하지 않습니다.

모든 참가자 표시는 닉네임만 사용합니다. 방 데이터는 자동 삭제하지 않으므로 행사가 끝나면 운영자가 Supabase에서 해당 방을 정리하세요. 운영 중에는 Vercel 함수 오류와 Supabase DB 상태를 확인할 수 있습니다. 오류 로그에는 DB 연결 문자열과 세션 토큰을 남기지 않습니다.

## 검증

```sh
npm run type-check
npm test
npm run puzzles:verify
npm run build
```

HTTP 통합 리허설은 로컬 서버 실행 후 `npx tsx scripts/smoke.ts`로 실행합니다. 이 스크립트는 별도 테스트 방을 만들고 3명의 참가자 입장, 라운드별 6건의 중복 제출, 결과 공개 및 전체 라운드 종료를 확인합니다. 진행자가 사용 중인 방은 변경하지 않습니다.

문제 8개는 고정 시드로 직접 생성했습니다. `npm run puzzles:generate`는 문제 파일을 다시 생성하는 개발용 명령입니다. 유일해 검증과 모바일 실제 기기의 난이도 리허설은 별개이므로 워크샵 전에 문제별 소요시간을 확인해 주세요. 방송 로고·영상·문제 이미지는 사용하지 않았습니다.
